# User-marked 12-space camera preset

`roi.spaces-12-20261110.json` follows the user's black outlines on
`WIN_20261110_17_10_12_Pro(1).jpg` (1920x1080). Capacity is confirmed by the user
as **12**, independent of the model's detected count. The reference photo
itself is not published in this repository.

Polygon order (P01-P12 in the preview):

| IDs | Spaces |
| --- | --- |
| P01-P06 | Six near-row spaces, from the turquoise car upwards |
| P07-P08 | Two upper-row spaces, silver car then pickup |
| P09-P12 | Four opposite-row spaces, bottom to top |

Coordinates are normalized to x/(1920-1), y/(1080-1); corners outside the
image are clipped to the image boundary. These outlines follow vehicle-body
regions drawn by the user, so this preset uses `anchor: "center"` rather than
the default `bottom_center`. A vehicle bounding box center must be inside at
least one outline. The annotation dot shows the selected reference point.
Legacy lot-boundary presets retain bottom-center behavior.

`capacity: 12` is calibration metadata, not a detected count, and is not sent
to the backend. JSON returned to the backend remains only the timestamp and
number of retained vehicle detections. These polygons filter detections; they
do not automatically classify each space or fill in missed cars. Duplicate
box suppression still happens in the selected detector. Some top/side spaces
and the turquoise car are partly clipped/obscured, so false vacancies remain
possible until the detector is validated on camera frames.

## Apply on the Pi

Pull `feature/yolo-roi`. From `~/terra/computer-vision`, stop the old camera
service with Ctrl+C, then:

```bash
cp roi.spaces-12-20261110.json roi.live.json
bash start-live.sh serve
```

Your `.env.pi` must contain the existing shared token and
`TERRA_ROI_FILE=roi.live.json`. If you previously chose another ROI path, update
it to `roi.live.json`. The local file takes priority over old shell exports.
The service reads its ROI at startup, so restart after any coordinate edits.
Only use this calibration with the same camera position, rotation and field
of view as the supplied photo. A scaled 16:9 view (such as 1280x720) is allowed;
a different aspect ratio is rejected. A different crop can still have the
same aspect ratio, so compare the actual Pi preview before relying on it.

## Apply on the laptop

Pull the same feature branch for the frontend changes. In `frontend/.env.local`,
set:

```dotenv
REACT_APP_TOTAL_CAPACITY=12
```

Restart `npm start`, and use http://localhost:3000/ without the old saved-demo
query string. Live view now defaults to 12; an existing explicit environment
value such as 11 still overrides the default and must be updated. The original
September saved-photo demo defaults to 11 when no override is present. No Java
source or database schema changed, so the backend JAR needs no rebuild.

The live display calculates `max(0, 12 - numOfCarsParked)`. It must use the
actual detected count, not a manually substituted 12. Review numbered boxes
in `captures/demand-annotated.jpg` against the physical spaces. The preset's
capacity does not establish detection accuracy or confirm every space is visible.
