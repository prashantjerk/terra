# Parking boundaries for the uploaded camera position

Preset: `roi.position-20261110.json`. It was traced from
`WIN_20261110_17_10_12_Pro.jpg` (1920 x 1080). Three polygons include the near
parking row, the opposite row, and the upper parking row while excluding the
central aisle, most striped access area, the grass, and the obstructed window
ledge. The lower turquoise car and some upper-edge cars are cropped; these
regions cannot establish the entire lot's capacity from this photo alone.

This is a draft geometric calibration, not a verified space inventory. Do
not set capacity to a detection count. Count actual marked stalls included
in the coverage area and confirm how to handle cropped/obstructed spaces.
For reliable availability it is preferable to reposition enough to see the
complete target area, then recalibrate. A moving car crossing a marked region
can still be counted; ROI filtering does not establish that it is parked.

Only apply this preset if the live Pi camera has the same framing as the
uploaded image. Matching 16:9 aspect ratio is necessary but does not prove
matching camera position, field of view, zoom, rotation or crop. The program
rejects incompatible aspect ratios. Scaling the same 16:9 frame to 1280x720
is supported. If the uploaded image came from a different camera, capture
`captures/live-frame.jpg` from the Pi and recalibrate that image instead.

On the Pi after pulling `feature/yolo-roi`, from `computer-vision/`:

```bash
cp roi.position-20261110.json roi.live.json
bash start-live.sh serve
```

Existing `.env.pi` must contain the shared token and camera settings, including
`TERRA_ROI_FILE=roi.live.json`. Stop any old camera service first. Backend/JAR
changes are not required. Review `captures/demand-annotated.jpg` before using
counts for availability. Configure frontend `REACT_APP_TOTAL_CAPACITY` only
after verifying the stalls covered by these regions.

The new multi-area format is:

```json
{
  "reference_size": [1920, 1080],
  "polygons": [
    [[0.0,0.0],[0.2,0.0],[0.2,0.5],[0.0,0.5]],
    [[0.7,0.0],[1.0,0.0],[1.0,0.5],[0.7,0.5]]
  ]
}
```

The example above illustrates the format, not the actual traced boundaries.
Legacy `polygon` configs continue to work. A vehicle's bottom-center must be
in at least one region; overlapping regions do not duplicate a count. The
editor now supports Finish area / add next to draw multiple regions, and
exports a reference image size for the aspect-ratio check.

Development photo check at confidence 0.5: SSD returned 5 retained detections,
and YOLOv8n returned 9. These are model outputs, not labeled ground truth;
visual inspection found inaccurate SSD boxes and missed vehicles. Camera
accuracy and cropped-space handling still need validation on site. The photo
itself is not included in this repository.
